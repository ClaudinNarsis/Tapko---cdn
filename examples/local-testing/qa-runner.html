Before Testing — Build Steps

1
Build the widget
npm run build
Compiles src/ → dist/tapko-widget.js via esbuild
2
Start the local dev server (serves dist/ on port 5501)
npx serve -l 5501 .
All test pages load the widget from http://localhost:8080/dist/tapko-widget.js
3
Open this runner from the same server
http://localhost:8080/examples/local-testing/qa-runner.html

Master QA Checklist

Run through each item — check off as you go

  • Widget initializes without console errors
    Open DevTools → Console. No errors on page load or Tapko.init()
  • Floating entry button renders at correct position
    Default: bottom-right. Button is 44px, visible, not clipped by overflow
  • Entering feedback mode shows 4% tint overlay
    Click entry button → overlay appears, cursor changes to crosshair
  • Clicking in feedback mode opens comment card
    Click anywhere on page → CommentCard appears near click point, not off-screen
  • Comment card UI — all elements present
    Text area, priority/weight selector, submit button, close button, screenshot indicator
  • Priority/weight selector works — all levels
    Cycle through all 5 priority levels. Selection is visually reflected on the card
  • Submitting a comment succeeds
    Type text → submit → card closes, pin appears at click location, no console errors
  • Pin persists on page (doesn't disappear after submission)
    Pin marker remains visible at the correct coordinates after card closes
  • Multiple comments on same page
    Submit 3+ comments. Each gets its own pin, no overlap or z-index bugs
  • Closing card without submitting
    Open comment card, press close/Escape — card dismisses, no pin left, no error
  • Exiting feedback mode restores normal cursor/interaction
    Click exit / press Escape — overlay gone, page links and buttons work again
  • Drawing mode activates and draws correctly
    Enable drawing mode via widget UI → draw a shape → shape persists on submit
  • Offline / failed submission goes to queue
    DevTools → Network → set Offline → submit comment → check QueueViewerModal shows it
  • Comment card stays within viewport
    Click near bottom-right corner — card repositions to stay on screen
  • Widget on mobile viewport (375px wide)
    DevTools → toggle device toolbar → 375×812 → widget visible, usable, not clipped
  • No z-index conflicts with page content
    Widget overlays appear above all page elements including sticky headers, modals
  • Shadow DOM styles don't leak into host page
    Widget styles don't affect host page fonts, colors, or layout
  • destroy() cleans up completely
    Run window.Tapko.destroy() in console → all widget elements removed, no errors
